# 阶段规划

本文件是实施计划的唯一出处。每阶段开工前对照本文件确认范围，
完工后在 [progress.md](progress.md) 记录实际交付与偏差。

注册、用户产品目录和香港试用部署的后续决策见
[后续功能计划](next-phase-registration-catalog-deployment.md)。已确定第一版使用邀请码、
昵称和密码注册；普通用户只能选择管理员已审核发布的产品；
搜索不到的产品不保存；部署优先在香港服务器试用并实测 Cloudflare 收益。

## 分支与交付流程

每个阶段一条特性分支，完工后合入 `main`：

```bash
git switch -c feature_s2
# ... 开发、提交 ...
git switch main && git merge --no-ff feature_s2
```

约定：

- 分支命名 `feature_s<n>`，与下表阶段编号对应。
- 合并用 `--no-ff` 保留阶段边界，便于回溯某个阶段改了什么。
- 合入 `main` 前四项质量门槛必须全绿：
  `ruff format --check`、`ruff check`、`mypy src/ledger`、`pytest`。
- 每阶段结束后暂停，由我（项目所有者）确认再进入下一阶段。

## 第一版范围边界

明确**不在**第一版内，避免范围蔓延：

- 登录银行抓取个人账户（属独立的私有连接器能力）
- OCR 自动识别（核查确认各来源均有接口或可解析页面，不需要 OCR）
- TWR / XIRR 等含现金流的百分比回报率
- 家庭共享、企业组织、代客管理
- 现金管理类产品纳入净值型收益计算（其专属指标可保存展示）
- 多币种汇总（人民币以外资产单独展示）

## 阶段清单

### S1 项目骨架与数据底座 — 已完成

建仓、模块化结构、PostgreSQL schema、迁移、容器编排、质量门槛。

交付：22 张表 / 240 字段；130 个测试；修复旧版 6 项 P0 问题。
详见 [progress.md](progress.md)。

### S2 多用户与业务数据 — 待确认开始

**目标**：多个用户各自管理账户、产品、交易、持仓，互不可见。

范围：

- 用户注册登录。本阶段**不开放注册**（`REGISTRATION_OPEN=false`），
  由管理员用 `ledger.cli create-admin` 建号试用功能。
  邮箱验证通道待域名备案后再定，接口预留但不启用。
- 会话管理：session 存稳定用户 ID，登录失败计数与阶梯锁定。
- 权限：普通用户与管理员分离；服务层从身份上下文取 `user_id`，
  不信任请求正文传入的 `user_id`。
- 银行账户、产品、交易流水的 CRUD。
- 持仓投影：由流水重建 `positions`（移动加权平均成本）。
- 审计事件记录。
- CSRF 与输入校验；产品名等用户数据用模板转义，不用 `innerHTML`。

验收：

- 两个用户读写同一产品互不影响。
- 用户 A 猜测用户 B 的账户、流水、导入文件 ID 时既不能读也不能写。
- 流水重放得到的持仓与逐笔累计一致。
- 复合外键阻止把自己的流水绑到他人账户（数据库层面拒绝）。

### S3 多来源采集

**目标**：净值自动入库，且每个数值可追溯到原始证据。

范围：

- 任务队列落地：`FOR UPDATE SKIP LOCKED` 领取、租约与 `lease_version`
  防旧 worker 覆盖、指数退避、`job_attempts` 明细。
- scheduler 按来源公布规律生成任务，`schedule_watermarks` 补发停机期间周期。
- 中银理财适配器（已实测接口可用，返回单位净值、累计净值、万份收益、
  七日年化、登记编码）。
- 中国理财网适配器（官方登记平台，覆盖全部机构）。
  `/prod/search` 入参需抓真实浏览器请求确定，这部分工作量单独评估。
- 原始证据存储与 sha256 去重；解析器版本记录。
- 行情选择：来源优先级、冲突容差、争议标记。
- 手工录入净值作为候选，管理员审核后才影响公共行情。

验收：

- 至少两个机构可采集并正确映射产品，代码映射不串产品。
- 分页覆盖目标日期区间。
- 重复点击同步、任务重复投递、租约过期重领均不重复记账。
- 接口返回空与「该来源不支持」是两种不同状态。
- 有冻结样本的契约测试，不依赖外部网络。

关于来源的核查结论（2026-10-01 实测）：

| 机构 | 结论 |
|---|---|
| 中银理财 | `bocwm.cn` JSON 接口可用，字段齐全 |
| 中国理财网 | `lcw-fe-service` 下有完整 API，机构列表已验证可取 |
| 浦银理财 | 官网为 Vue 动态页，有净值图表，接口待抓 |
| 光大理财 | 官网返回 412，有反爬，需浏览器渲染 |
| 交银理财 | 未找到可用官网入口 |
| 苏银理财 | 未找到可用官网入口 |

决定：统一走中国理财网作为主来源，各机构官网作为补充。

### S4 收益跟踪

**目标**：按日/周/月/自定义区间看收益，每个数字能说明口径。

范围：

- 交易重放生成日快照（`position_snapshots`、`portfolio_snapshots`）。
- 收益口径按 `repo.wiki/03-data-and-returns.md`：
  移动加权平均成本；未实现收益 `U = M - C`；
  已实现收益 `G = R - 已赎回成本 + D - F`；累计 `P = U + G`。
- 申赎、现金分红、红利再投（成对登记）、手续费。
- 数据完整性标记：`missing` / `carried_forward` / `stale` / `partial`,
  缺净值时金额为 null，不用 0 冒充。
- 区间净值年化用实际起止日期，不用固定 7/14 天分母。
- 净值修订后从受影响日期重算，与行情更新同事务提交。
- Excel/账单导入：预览 → 确认两步，文件 hash 去重。

验收用例（每个都要有已知预期值）：

- 固定份额、分批买入、部分赎回、全部赎回、现金分红、红利再投、
  手续费、期初迁移、缺失净值、跨周末、历史补录、净值更正。
- wiki 里的基准例：买入 100 份成本 100，净值 1.10 时赎回 40 份到账 44，
  期末剩余成本 60、市值 66、未实现 6、已实现 4、累计 10。
- 同一计算版本内日收益累加等于对应周/月区间金额。

### S5 手机端页面

**目标**：手机浏览器上好用，可加到桌面。

范围：

- Jinja2 模板 + Alpine.js（无构建工具链）。
- 持仓卡片列表、产品详情净值走势、收益日历、手工记净值、管理页。
- ECharts 画净值走势，移动端适配。
- PWA：manifest + Service Worker，可加桌面图标。
- 收益计算全部在服务端，前端只做格式化。
- 展示估值日期、数据来源、完整性状态。

验收：在手机上实际完成一遍记账与查看收益的完整流程。

### S6 阿里云部署

**目标**：demo 可用，先限定几人访问。

范围：

- ECS（建议 2 核 4G / Ubuntu 24.04）+ Docker Compose。
- PostgreSQL 先容器自建，数据量上来再评估迁 RDS。
- Caddy 反向代理 + 自动 HTTPS（域名备案完成后启用）。
- demo 阶段不开公网：安全组白名单限定 IP，或 Tailscale。
- 安全组只开 80/443，数据库不暴露。
- 安全响应头：CSP、HSTS、X-Content-Type-Options。
- 每日加密备份 + 恢复演练；结构化日志与基础告警。
- 管理员手工建号，验证功能后再决定是否开放注册。

验收：空库建表、建管理员、登录、采集、看收益全流程通过；
重启保留数据；上一镜像可回滚。

### S7 按真实需求扩展

视实际使用情况决定：开放注册与邮箱验证、更多银行来源、
私有账户连接器、TWR/XIRR、关注提醒、独立消息队列。

每项独立验收，不把未支持的指标混进已支持的收益展示。
