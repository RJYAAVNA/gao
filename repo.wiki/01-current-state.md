## 当前数据关系

- `users` 只有登录身份，没有和业务数据建立关系。
- `products` 同时保存产品信息、当前份额、成本和购买日期，没有 `user_id`。
- `nav_history` 以 `(code, date)` 唯一，没有机构、份额类别和来源维度。
- `sync_logs` 是全局文字日志，缺少任务、产品、错误类型等结构化字段。

当前代码能录入多个机构的产品，但不能据此认定已经支持多个银行的自动采集。`sync_all()` 把所有代码都传给中银接口；其注释称非中银返回空，实际没有机构过滤。接口返回空就显示“无公开接口”，只能说明这次未得到数据，不能证明该机构没有公开接口。前端对其他机构的同类表述也未经本次验证。

## 优先处理的问题

| 优先级 | 代码证据 | 影响与处理建议 |
| --- | --- | --- |
| P0 | Compose `build: .`，文件名却为 Dockerfile.txt | 默认构建找不到 Dockerfile；统一命名或显式指定路径 |
| P0 | `init_db()` 只在 `__main__` 调用，镜像运行 `app:app` | 空数据卷用 Gunicorn 首启不会建表；独立迁移/初始化步骤 |
| P0 | API 查询和修改不含用户条件 | 多用户会读写同一份持仓；必须先落地所有权和越权测试 |
| P0 | 源码与 Compose 有默认密码/密钥，源码内嵌持仓 | 上线必须注入独立凭据，清理真实种子；不在文档重复凭据 |
| P1 | 调度器在 import 阶段启动 | 扩容和滚动重启可能重复执行；独立调度进程和数据库去重 |
| P1 | 串行网络请求发生在同步 API 内 | 多个 15 秒超时可能超过 Gunicorn 60 秒请求超时；改为异步任务 |
| P1 | 写入净值后循环仍继续联网，结束才 commit | SQLite 写事务可能长期持锁；网络抓取与短事务分开 |
| P1 | 当前份额用于所有历史日期的收益日历 | 申赎、分红或修改持仓后历史结果失真；以流水重建历史 |
| P1 | 年化取目标日前最近净值，却固定使用 7/14 天分母 | 缺日时区间不一致；以实际起止日期计算 |
| P1 | 各产品“最新收益”直接相加 | 不同净值日期被混成同一汇总；使用统一估值日和完整性标记 |
| P1 | `nightly_sync_job` 吞掉异常，有一只成功即记成功 | 缺少真实失败信号；结构化部分成功状态、告警和重试 |
| P1 | `INSERT OR REPLACE` 覆盖净值 | 丢失修订证据；保留版本、来源和重算任务 |
| P1 | 页面通过 innerHTML 插入产品名等数据 | 有脚本注入风险；模板转义或 textContent，并补 CSRF 与输入校验 |
| P2 | `REAL` / float / JS Number 计算金额 | 使用 Decimal/NUMERIC，显示时再舍入 |
| P2 | 依赖只有版本下限、无测试和发布流程 | 锁定依赖，建立迁移、收益和采集契约测试 |

上述结论来自静态检查。本次未运行应用、未连接银行接口、未修改台账或修复现有代码，因此不把架构设计描述成已验证的部署结果。
