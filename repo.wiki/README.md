## 第一版的目标

用户登录后管理自己的银行账户、理财持仓和交易记录；平台按产品配置从公开 API 或网页提取净值，提供人工录入兜底；按日、周、月和自定义区间观察收益，能够说明数据日期、来源、完整性和计算方式。

建议采用 **Flask 模块化单体 + PostgreSQL + 独立 scheduler/worker**。复用现有移动端页面，优先拆分数据与业务逻辑。第一版使用数据库持久任务队列，暂不引入 Redis、微服务或 Kubernetes；浏览器/OCR 按实际数据源需求接入。

## 默认边界与待确认事项

- 初始面向小规模用户，单区域部署，业务时区 Asia/Shanghai，第一版收益统计以人民币净值型产品为主。
- “多银行”包含销售银行和理财发行机构两个维度，两者必须分开建模。
- 自动拉取的第一目标是公开产品资料与行情。个人持仓通过人工录入、账单导入进入系统；登录银行后抓取个人账户属于另一个需单独实现的连接器能力。
- 第一版支持多用户独立数据，不预设家庭共享、企业组织或代客管理。
- 现金管理产品的万份收益、七日年化可以保存和展示，但在独立估值模型完成前不纳入净值型收益计算。
- 首批具体银行、产品清单、可用页面/接口、部署机器和可接受的数据延迟尚未指定；第二个自动化来源需先验证可访问性和字段口径，再承诺接入。

## 核心决策

| 决策 | 原因 |
| --- | --- |
| 产品行情共享，持仓与流水按用户隔离 | 同一产品只采集一次，不同用户独立记账 |
| 用交易流水重建持仓，保存每日快照 | 当前份额无法代表历史份额 |
| 采集离开 Web 请求和 Web 进程 | 避免请求超时、滚动发布重复调度 |
| API → HTML/DOM → 浏览器 → OCR | 优先稳定、可校验的结构化数据 |
| 原始证据、解析版本和净值修订可追溯 | 网页改版、OCR 错误和历史更正能够复核重算 |
| 小步迁移、先兼容扩展再清理旧字段 | 支持持续部署与应用回滚 |

后续每次新增数据源、修改收益公式、数据库迁移或发布方式，随代码同步更新对应 Wiki 页面，并注明决策变化。
